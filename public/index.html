Theory

How an executor works

A Roblox executor does three things: it attaches to the game process, finds the Lua state that runs game scripts, and injects a new function into it. Once injected, the function has the same access as any game script — that is why executors are powerful, and why this lab keeps everything inside the sandbox.

  1. Attach — get a handle on the process
  2. Enumerate — find the scripting environment
  3. Inject — add loadstring, getgenv, the console…
  4. Execute — run your Lua inside the realm

Two realms, one truth

The server owns the world. The client owns the experience: camera, GUI, input. They talk in exactly one way — RemoteEvent. 

-- client
remote:FireServer(position)

-- server
remote.OnServerEvent:Connect(function(player, pos)
  -- never trust the client
end)

What this sandbox blocks

This lab deliberately cannot touch your computer. io, os.execute, loadfile and HTTP requests are removed from the Lua state, and scripts run on a budget so a while true do end cannot freeze the engine.

That is the difference between this teaching tool and a real executor: real ones run inside Roblox, on someone else's machine.
